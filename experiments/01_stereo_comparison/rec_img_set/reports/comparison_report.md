# `rec_img_set` 上 IGEV++ RT 与 LiteAnyStereo 统一可行性测试报告

**报告日期：** 2026-08-13  
**测试目的：** 在统一输入、统一裁剪、统一参考和统一点云处理标准下，验证 LiteAnyStereo LAS1 相对一期 IGEV++ RT 的视差估计和三维重建可行性。  
**测试边界：** 本报告覆盖双目图输入、模型推理、视差图、定量评价和点云文件生成；不覆盖 RK3588/RKNN 部署、模型训练、点云后续配准、尺寸测量或真实精度标定。  
**核心结论：** LiteAnyStereo 可以作为后续工程验证的优先候选。它在 FDJYP-3 全 73 场的五项宏平均指标均优于 IGEV++ RT，核心推理约快 `3.18×`，并显著降低少数场景的灾难性失效风险；但 IGEV++ RT 在更多普通单场上仍取得略低 EPE，LiteAnyStereo 也存在反例，因此不能表述为逐场全面领先。螺纹和 `rectified_images` 数据存在明显极线几何风险，当前生成的点云只能证明流程可运行，不能证明几何精度合格。

## 1. 为什么需要本次重新测试

已有报告 `JMP_LITEANYSTEREO_TEST_REPORT_zh-CN.md` 已经统一了参考视差和指标函数，但当时存在两个限制：

1. LiteAnyStereo 从 `JMP-LF6020-ETH3D` 读取重新整理后的图像，而 IGEV 使用历史保存视差；虽然两套 FDJYP-3 图像像素差异极小，但不是严格意义上的同一文件输入；
2. 当时本机没有一期 IGEV++ RT 代码和 checkpoint，因此没有重新执行 IGEV 网络前向，也无法进行同机速度和显存比较。

本次已找到并验证 IGEV++ RT 官方 SceneFlow 权重。对历史 `igev_output` 的复现检查确定一期输出对应以下参数：

```text
max_disp = 128
valid_iters = 16
precision = FP32
```

使用这套参数重新运行时，73 场历史结果与本机结果的平均绝对差约 `0.098 px`、相关系数约 `0.99970`。两者不是逐位相同，差异主要来自旧服务器与当前 RTX 4090/PyTorch/CUDA 浮点环境，但足以确认模型和处理链路一致。

因此本报告不再读取历史 `igev_output` 作为主测试结果，而是让 IGEV++ RT 和 LiteAnyStereo 逐场读取完全相同的 `rec_img_set` PNG 并在同一台 GPU 上重新推理。

## 3. 统一测试协议

### 3.1 两模型共同设置

| 项目 | 本次统一设置 |
| :--- | :--- |
| 输入文件 | 同一场景同一份 `rec_img_set/<group>/<scene>/im0.png`、`im1.png` |
| 输入分辨率 | `1280×720`（高×宽），宽度镜像填充到 736 后推理 |
| 输入色彩 | OpenCV BGR 读取后统一转 RGB tensor |
| 数值精度 | FP32 |
| 固定评价/点云 ROI | `disp[234:1052, 126:638]`，得到 `818×512` |
| 定量参考 | FDJYP-3 的 Foundation Stereo `disp_cropped.npy` |
| 有效掩码 | 参考视差有限且 `>0` |
| 指标 | EPE、D1、Bad1、Bad2、Bad3，同一函数计算 |
| 汇总 | 先逐场计算，再按场景做宏平均 |
| 主结果 | 全 73 场，不排场景、不按 EPE 过滤 |
| 辅助结果 | 历史固定排除 4 场后的 69 场；仍不做模型独立 EPE 过滤 |

D1 定义为绝对误差大于 3 px 且相对误差大于 5% 的像素比例。Bad1/2/3 分别是绝对误差超过 1/2/3 px 的像素比例。

这里的 Foundation Stereo 结果是工程评价参考，不是人工标注真值，也不是可溯源的激光扫描真值。报告中的“更准”仅表示“相对该参考误差更低”。

### 3.2 模型配置

| 项目 | IGEV++ RT | LiteAnyStereo LAS1 |
| :--- | :--- | :--- |
| 代码入口 | `IGEV-plusplus/core_rt` | `LiteAnyStereo/core/liteanystereo.py` |
| checkpoint | RT SceneFlow | 官方 LAS1 |
| SHA-256 | `7b7b6ac4...cbaa9209` | `ee0c3a0d...ec1b9b1` |
| checkpoint 文件大小 | 16.17 MiB | 29.35 MiB |
| 参数量 | 4,165,162 | 7,603,626 |
| 最大视差 | 128 px | 192 px |
| 更新迭代 | 16 | 非迭代单次前向 |
| 推理精度 | FP32 | FP32 |

两模型最大视差不同并非漏配参数：IGEV 使用已复原并能匹配一期历史输出的 `128/16` 配置；LAS1 官方模型在现有报告和项目入口中使用 `192`。这代表两套当前实际工程候选配置，而不是单纯控制网络结构变量的消融实验。

### 3.3 点云生成标准

本次从两模型的同一固定 ROI 视差生成 PLY，处理完全一致：

1. 视差双边滤波：`d=5, sigmaColor=50, sigmaSpace=50`；
2. 有效视差范围：`5–192 px`；
3. 有效深度范围：`0<Z<200`；
4. 黑色背景阈值：RGB 三通道并非全部 `≤50`；
5. 固定裁剪后同步调整 Q：`Q[0,3]+=126`、`Q[1,3]+=234`；
6. 保存带 RGB 颜色的二进制 PLY。

标定矩阵按数据组选择：

| 数据组 | Q 来源 | 依据与限制 |
| :--- | :--- | :--- |
| FDJYP-0、FDJYP-3 | `stereo_gongjian.yml` | FDJYP-3 矫正图用 `gongjian_map` 重映射可逐像素完全复现；JMP 整理目录也保留相同 FDJYP 相机参数 |
| 螺纹 | `stereo_luowen.yml` | 使用仓库中明确命名的螺纹标定 |
| `rectified_images`、刻度 | `stereo.yml` | 历史 `save_rectified.py` 选择的 1221 配置；源采集标定追踪信息不完整 |

历史点云脚本曾在不同数据上硬编码 JXP Q，本次没有沿用该做法。若 Q 与实际矫正图不匹配，即使 PLY 能打开，尺寸和深度也会产生系统性错误。

| LiteAnyStereo LAS1 | **2.0762** | **7.4666** | **40.1102** | **17.4400** | **9.8854** |

LiteAnyStereo 相对 IGEV++ RT：

| 指标 | 绝对降低 | 相对降低 |
| :--- | ---: | ---: |
| EPE | 2.5977 px | **55.58%** |
| D1 | 3.1747 个百分点 | **29.83%** |

全 73 场五项宏平均均由 LiteAnyStereo 取得更低数值。Bad1 的优势很小，说明 1 px 级局部误差仍是两者共同短板；D1、Bad2、Bad3 和 EPE 的改善更明确。

### 4.2 场景分布与尾部稳定性

| 统计项 | IGEV++ RT | LiteAnyStereo |
| :--- | ---: | ---: |
| 单场 EPE 中位数 | 2.0420 | **1.6224** |
| 单场 EPE 标准差 | 14.0770 | **1.8682** |
| P90 EPE | 3.9263 | **3.7448** |
| P95 EPE | 14.3584 | **4.3322** |
| 最大 EPE | 108.7883 | **12.3171** |
| EPE >10 px 场景数 | 5 | **1** |
| EPE ≤3 px 场景数 | 56 | **60** |
| 单场 EPE 获胜数 | **44** | 29 |

![逐场 EPE 分布](../results/final_203/report_assets/epe_distribution.png)

这组数据说明两个同时成立的事实：

- IGEV++ RT 在 `44/73` 场取得更低单场 EPE，说明它在许多普通场景中仍有小幅优势；
- LiteAnyStereo 的平均值、中位数和尾部指标更好，主要因为它显著降低了极端失败幅度。

如果只保留“两模型 EPE 都不超过 10 px”的 68 个常规场景，IGEV EPE 为 `1.8987 px`，LiteAnyStereo 为 `1.7932 px`，LiteAnyStereo 仍略优约 `5.56%`，但差距远小于全量结果中的 `55.58%`。因此不能把全部平均改善都解释为每张图上的普遍精度提升；更准确的解释是：常规场景略有提升，加上困难场景明显更稳。

## 6. 推理速度、模型规模与显存

测试环境：RTX 4090、PyTorch `2.6.0+cu126`、CUDA `12.6`、cuDNN `90501`、OpenCV `4.11.0`。两模型均 FP32，执行一次预热后统计 203 场；计时前后执行 CUDA 同步。

| 方法 | 核心推理均值 | 中位数 | P95 | FPS（由均值换算） |
| :--- | ---: | ---: | ---: | ---: |
| IGEV++ RT | 115.09 ms | 115.18 ms | 116.32 ms | 8.69 |
| LiteAnyStereo LAS1 | **36.16 ms** | **36.11 ms** | **37.22 ms** | **27.65** |

LiteAnyStereo 核心前向延迟降低约 `68.58%`，速度约为 IGEV++ RT 的 `3.18×`。

![核心推理速度](../results/final_203/report_assets/runtime.png)

| 资源项 | IGEV++ RT | LiteAnyStereo LAS1 |
| :--- | ---: | ---: |
| 参数量 | **4.17 M** | 7.60 M |
| checkpoint 大小 | **16.17 MiB** | 29.35 MiB |
| torch 峰值 allocated | 711.03 MiB | **658.87 MiB** |
| 相对模型常驻后的增量峰值 | 694.91 MiB | **597.61 MiB** |

显存数字由两个独立新进程分别测量，预热一次后重置峰值统计，只适用于当前 PyTorch CUDA allocator 和输入尺寸。它不是 `nvidia-smi` 的整进程显存，也不代表 RKNN/NPU 占用。

完整流水线平均约 `753 ms/场`，但其中包含两模型串行推理、SIFT 极线审计、四个大数组写盘、两张 PLY 生成以及多张 PNG 压缩，不能用于部署 FPS。工程实时性应以核心前向延迟或部署后的端到端实现为准。

## 7. `rec_img_set` 跨数据组可行性与数据风险

### 7.1 极线质量审计

本报告使用图像特征匹配估计左右图的垂直残差：

- `good`：中位垂直残差 ≤1 px；
- `warning`：1–5 px；
- `high_risk`：>5 px；
- 匹配不足 8 个则为 `unknown`。

该审计不是标定重投影误差，但可作为发现明显极线错位的可重复代理检查。

| 数据组 | good | warning | high_risk | 垂直残差中位数 |
| :--- | ---: | ---: | ---: | ---: |
| FDJYP-0 | 56 | 26 | 0 | 0.854 px |
| FDJYP-3 | 66 | 7 | 0 | **0.605 px** |
| 螺纹 | 1 | 32 | 4 | 2.643 px |
| `rectified_images` | 0 | 0 | 6 | **7.968 px** |
| 刻度 | 4 | 1 | 0 | 0.692 px |

![极线质量分布](../results/final_203/report_assets/geometry_audit.png)

FDJYP-3 与刻度组整体满足水平双目输入要求；FDJYP-0 部分场景需要复核。螺纹组大部分是 warning，4 场 high-risk；`rectified_images` 6 场全部 high-risk。后两组即使模型输出连续视差，也可能是在补偿错误几何，不能据此判断真实深度可靠。

### 7.2 无参考数据上的模型一致性

| 数据组 | 两模型 MAE 均值 | MAE 中位数 | 相关系数均值 | 解释 |
| :--- | ---: | ---: | ---: | :--- |
| FDJYP-0 | 3.661 px | 2.275 px | 0.798 | 有一定一致性，但部分场景差异明显 |
| FDJYP-3 | 3.394 px | **0.420 px** | 0.904 | 中位数很小，均值受少数失败场景拉高 |
| 螺纹 | 14.443 px | 4.739 px | 0.553 | 模型分歧较大，且极线风险高 |

![跨组代表案例](../results/final_203/report_assets/representative_feasibility.jpg)

刻度样例 `camera-202512081522-0004` 中，两模型视差 MAE 约 `0.216 px`、相关系数约 `0.9993`，显示当前算法可以在高纹理表面产生高度一致的连续视差。螺纹和一般新图则存在大范围模型分歧，应优先修正极线标定后再谈模型优劣。

## 8. 点云输出检查

| 数据组 | IGEV++ RT | LiteAnyStereo |
| :--- | ---: | ---: |
| FDJYP-0 | 276,881 | 276,784 |
| FDJYP-3 | 383,544 | 383,468 |

## 9. 算法可行性判断

### 9.1 已得到证据支持的结论

1. **推理链路可行：** 203 组唯一已矫正图全部完成两模型前向，无崩溃、无非有限输出；
2. **视差输出可行：** 每场均保存完整 `1280×720` 浮点视差、固定 ROI 浮点视差和统一色标 PNG；
3. **点云链路可行：** 203 场各生成两份可读取带色 PLY，共 406 份；
4. **定量候选优先级：** 在有正式参考的 73 场中，LiteAnyStereo 的总体精度和困难场景鲁棒性更好；
5. **速度可行：** 当前 RTX 4090 FP32 核心前向约 36 ms，具备继续做工程优化和部署适配的价值；
6. **刻度场景初步可行：** 5 场都能推理和生成点云，其中 4 场极线审计 good，两模型总体接近。

### 9.2 尚未得到证据支持的结论

1. 不能声称 LiteAnyStereo 每个场景都优于 IGEV；
2. 不能声称输出点云达到毫米级或任何绝对测量精度；
3. 不能用 Foundation Stereo 参考代替人工/激光真实真值；
4. 不能根据点云文件成功写出就判断螺纹和 `rectified_images` 几何正确；
5. 不能把 RTX 4090 的 PyTorch FP32 速度直接外推到 RK3588；
6. 不能从这次结果判断量化、ONNX 或 RKNN 转换后的数值一致性。

### 9.3 推荐决策

现阶段建议把 **LiteAnyStereo LAS1 作为二期优先工程候选，IGEV++ RT 保留为强基线和回归对照**。理由不是“每场都更准”，而是：全量指标更低、异常场景失效幅度更小、核心推理快约 3.18 倍、当前 CUDA 显存峰值略低。

不建议立即删除 IGEV 路线。IGEV 在更多普通单场上仍略优，并且在 `0038/0040/0042` 等场景存在明确反例。后续若做模型优化，应重点分析 LAS 在规则重复结构、边缘和细节处的误差，而不是只继续压低全量均值。

## 10. 后续建议与优先级

1. **先修数据几何：** 重新核对螺纹和 `rectified_images` 的原始标定、左右图命名、旋转方向和 remap 来源；目标是把中位垂直残差压到 1 px 以内；
2. **建立数据 manifest：** 为每组图记录采集批次、标定 YAML、map SHA-256、是否矫正、Foundation Stereo 版本、测试/训练归属；
3. **补充真实几何验证：** 至少选平面、标准台阶、已知刻度和螺纹标准件，用激光扫描或已知尺寸评价平面残差、尺度误差和边缘误差；
4. **专项分析反例：** 对 `0038/0040/0042` 和刻度细节增加边缘区、局部 ROI、平面拟合和点云粗糙度指标；
5. **部署前回归集：** 固定保留 73 场全量结果，不做按模型独立过滤；同时加入刻度 5 场和修正后的螺纹场景；
6. **再做部署评估：** 完成 ONNX 导出一致性、FP16/INT8 量化误差、RKNN 算子兼容和板端端到端延迟测试；
7. **控制输出存储：** 当前全量产物约 6.0 GiB。正式流水线可保留 ROI 浮点视差和 PLY，把完整视差与 PNG 设为按需输出。

## 12. 最终结论

本次统一重跑确认：LiteAnyStereo 已具备继续用于杰泰二期双目三维重建工程验证的可行性。它在同一 `rec_img_set` 输入、同一参考、同一 ROI 和同机 FP32 环境下，相对 IGEV++ RT 获得更低的全量 EPE/D1/Bad1/Bad2/Bad3，更关键的是把 IGEV 的少数极端失效显著压低，同时核心推理速度提高约 3.18 倍。

但这仍是“模型候选可行”而非“最终测量系统合格”。当前最需要解决的限制已经从单纯换模型转向数据和几何工程：螺纹及一般新图的极线质量不足，标定追踪不完整，Foundation Stereo 不是严格真值，点云也尚未经过标准件尺度验证。下一阶段应先统一标定与数据清单，再用真实几何基准验证点云测量精度，然后再推进 RK3588 部署。
