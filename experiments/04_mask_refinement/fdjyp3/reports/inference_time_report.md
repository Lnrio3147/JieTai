# 实验 1–4 加入 BiSeNetV2 后的总模型推理时间报告

**测试日期：** 2026-08-25
**测试对象：** LiteAnyStereo LAS1 + 人工标注 BiSeNetV2 + 实验 4 Mask 修复
**测试数据：** FDJYP-3，原始双目图高 1280、宽 720
**测试设备：** NVIDIA GeForce RTX 4090 24 GB
**测试结论：** 稳定态完整链路平均约 **50.33 ms/场**，约合 **19.87 FPS**；如果只统计两个神经网络的核心前向，平均约 **31.14 ms/场**，约合 **32.12 FPS**。

## 一、汇报摘要

本次对实验 1–4 最终形成的工件主体视差链路进行了推理时间测试：

```text
校正左图 + 校正右图
        ├── LiteAnyStereo LAS1 ──> 全图视差 ───────────────┐
        └── 人工标注 BiSeNetV2 ──> 前景概率 ──> 实验4修复 ├──> 主体视差
                                                          ┘
```

实验 2 和实验 3 是 BiSeNetV2 的前后两代训练阶段，不是推理时串行执行的两个模型。最终链路只使用实验 3 的人工标注冻结模型；实验 4 是概率上采样、闭运算、最大连通域筛选和视差连续性补洞等 CPU 后处理。

主要结果如下：

| 统计口径 | 平均耗时 | 由均值换算的吞吐率 |
| --- | ---: | ---: |
| LiteAnyStereo 核心前向 | 28.17 ms | 35.50 FPS |
| LiteAnyStereo + BiSeNetV2 核心前向 | **31.14 ms** | **32.12 FPS** |
| 两模型含内存中预处理和结果回传 | 40.47 ms | 24.71 FPS |
| 实验 4 修复与主体视差生成 | 9.86 ms | — |
| **实验 1–4 稳定态完整链路** | **50.33 ms/场** | **19.87 FPS** |

相较只运行 LiteAnyStereo 的完整单阶段耗时 `35.07 ms`，加入 BiSeNetV2 和实验 4 后处理后增加 `15.27 ms`，延迟增加约 `43.54%`，吞吐率由约 `28.52 FPS` 降至约 `19.87 FPS`。

## 四、测试口径

本报告提供两个互补口径。

### 4.1 核心模型前向

只统计已经位于计算设备上的输入进入网络，到网络输出完成为止的耗时。CUDA 计时前后均同步，模型加载和预热不计入结果。

### 4.2 稳定态完整链路

统计以下内容：

1. 内存中的 OpenCV BGR 图像转换、缩放和归一化；
2. CPU/GPU 输入传输；
3. LiteAnyStereo 和 BiSeNetV2 前向；
4. 输出回传 CPU；
5. 实验 4 Mask 修复；
6. 主体视差数组生成。

以下内容不计入推理时间：

- Python、PyTorch 和 TensorFlow 冷启动；
- 模型文件读取和图构建；
- 原始 PNG、概率 NPY、视差 NPY 的磁盘读写；
- 可视化图片、CSV、PLY 点云和报告生成；
- 两个独立环境之间可能采用的文件或进程通信。

因此，`50.33 ms` 表示模型常驻内存后的稳定态串行计算预算，适合评估算法本身是否接近实时；它不是当前离线脚本从启动到写完全部结果的墙钟时间。

## 五、详细测试结果

### 5.1 核心前向

首轮每个神经网络预热 30 次，随后测量 200 次：

| 模块 | 平均 | 中位数 | P95 | 最小值 | 最大值 |
| --- | ---: | ---: | ---: | ---: | ---: |
| LiteAnyStereo LAS1 | 28.17 ms | 28.04 ms | 29.76 ms | 26.46 ms | 31.19 ms |
| BiSeNetV2 | 2.97 ms | 2.55 ms | 3.61 ms | 2.29 ms | 58.90 ms |
| **两模型均值串行合计** | **31.14 ms** | — | — | — | — |

BiSeNetV2 核心前向出现一次 `58.90 ms` 的离群点，与测试时 GPU 上存在其他常驻进程相符；其中位数和 P95 更能反映无抢占时的稳定性能。两个模型的 P95 来自独立测试，不能直接相加解释为完整链路 P95。

### 5.2 含预处理、传输和后处理的完整链路

为确认稳定性，完整阶段进行了两轮独立复测：

| 阶段 | 第一轮平均 | 第二轮平均 | 两轮平均 |
| --- | ---: | ---: | ---: |
| LiteAnyStereo：预处理 + 前向 + 视差回传 | 35.81 ms | 34.32 ms | **35.07 ms** |
| BiSeNetV2：预处理 + 前向 + 概率回传 | 5.27 ms | 5.53 ms | **5.40 ms** |
| 实验 4 修复 + 主体视差生成 | 10.16 ms | 9.57 ms | **9.86 ms** |
| **串行总计** | **51.25 ms** | **49.42 ms** | **50.33 ms** |

两轮结果相差 `1.83 ms`，完整链路平均值落在 `49.42–51.25 ms/场`。各阶段中位数相加约为 `47.6–48.6 ms`，说明大多数帧可以达到约 `20–21 FPS`，但使用平均值进行工程预算时应按约 `19.87 FPS` 估计。

### 5.3 延迟构成

以两轮平均 `50.33 ms` 计算：

| 阶段 | 耗时占比 |
| --- | ---: |
| LiteAnyStereo 完整阶段 | 69.67% |
| BiSeNetV2 完整阶段 | 10.73% |
| 实验 4 后处理 | 19.60% |

BiSeNetV2 本身不是主要瓶颈。加入分割后新增的耗时中，实验 4 CPU 后处理约占 `64.62%`，高于 BiSeNetV2 的前向、预处理和输出回传之和。因此，如果需要继续提高总 FPS，应优先优化连通域和孔洞处理，而不是首先缩减 BiSeNetV2。

## 六、结果一致性检查

测速使用正式模型、正式权重和正式实验参数，并与已有实验输出进行回归核对：

| 检查项 | 结果 |
| --- | --- |
| LiteAnyStereo 当前前向与正式保存视差 | 平均绝对差 `3.37e-5 px`，属于 CUDA 浮点执行差异 |
| BiSeNetV2 当前前向与正式保存概率 | 平均绝对差 `9.56e-6` |

这说明本次测速执行的是实验 1–4 的正式处理链路，没有误用伪标签模型、旧权重或其他实验分支。

## 七、结论与汇报表述

建议在汇报中使用以下结论：

> 在 RTX 4090、batch=1、FP32 条件下，LiteAnyStereo 加入人工标注 BiSeNetV2 和实验 4 掩膜修复后，两个神经网络核心前向约 31.14 ms；包含内存中图像预处理、结果回传、掩膜修复和主体视差生成的稳定态完整链路约 50.33 ms/场，对应约 19.87 FPS。BiSeNetV2 仅增加约 5.40 ms，当前新增耗时的主要来源是约 9.86 ms 的 CPU 掩膜后处理。

工程判断：

1. 在 RTX 4090 上，该链路已经接近 `20 FPS`，适合离线批处理和中等实时性演示；
2. 若目标是稳定不低于 `20 FPS`，当前余量较小，应消除 GPU 竞争并优化实验 4 后处理；
3. 当前结果不能直接外推到 RK3588、TensorRT、ONNX Runtime 或 RKNN，目标设备必须重新测速；
4. 当前 PyTorch/TensorFlow 双环境采用分阶段实测。正式部署若引入进程通信或磁盘中转，需要把相应开销计入最终设备端端到端延迟；
5. 冷启动和模型加载不属于单帧稳定态推理，但对一次性任务或短批次任务仍应另行测量。

## 八、后续优化建议

按预期收益排序：

1. 将实验 4 连通域、孔洞候选和形态学运算合并，减少全分辨率数组扫描和临时布尔数组；
2. 仅在主体包围盒或固定 ROI 内执行孔洞分析，避免每帧多次处理完整 `1280×720` Mask；
3. 将 BiSeNetV2 转为 ONNX/TensorRT 或与双目模型统一部署引擎，减少双框架和跨进程集成成本；
4. 在独占 GPU、固定时钟和正式服务进程中重新采集完整延迟分布；
5. 在最终目标设备上同时报告平均值、中位数、P95、冷启动时间和峰值内存，形成正式部署基线。
